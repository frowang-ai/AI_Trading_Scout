# yunwu 自动守护工具技术科普

## 目标概览
- 监控现有的 `extract_matched_procurement_info.py` 批量处理脚本。
- 在出现 Yunwu API 集中失败时自动熔断、等待 5 分钟后重启。
- 运行期间提供实时健康状态，方便观察进度与异常。
- 对原有业务代码零侵入，仅新增守护脚本与配套配置。

## 核心技术栈

### 1. 子进程管理
- **库**：Python 标准库 `asyncio`、`subprocess`、`signal`。
- **方式**：通过 `asyncio.create_subprocess_exec` 启动主脚本，相当于执行 `python extract_matched_procurement_info.py`。
- **特性**：
  - 可异步等待子进程退出，不阻塞守护程序。
  - 支持优雅终止：先发送 `SIGINT`，超时未退出再升级到 `SIGTERM`/`SIGKILL`。
  - 可在每次启动前记录原因（首次启动、失败重启、人工请求等）。

### 2. 日志捕获与解析
- **数据源**：主脚本写入的 stdout/stderr 文本日志以及 Yunwu JSONL 跟踪文件。
- **捕获手段**：在创建子进程时设置 `stdout=subprocess.PIPE`、`stderr=subprocess.PIPE`，使用 `await process.stdout.readline()` 异步逐行读取。
- **解析逻辑**：
  - 识别类似 `[call_xxx] ⚠️ API连接失败`、`❌ 调用失败: 连接错误: Request timed out.` 的关键行。
  - 使用 `collections.deque` 维护滑动窗口，统计失败事件密度和连续失败次数。
  - 可选读取 `logs/matched_procurement_*.jsonl`，借助 `json` 标准库进一步验证失败类型。

### 3. 健康状态面板
- **实现方式**：标准库 `asyncio` + `print("\r...")` 或简单 `logging` 输出，实时刷新当前批次、最近成功/失败、连续失败计数等。
- **可扩展**：若需更丰富的界面，可结合第三方库 `rich`、`textual` 创建动态面板，但基础方案仅用标准库即可实现。

### 4. 熔断与冷却策略
- **判定条件**：
  - 滑动窗口（默认 120 秒）内失败占比超过阈值（例如 80%）。
  - 连续出现若干条失败日志（例如 15 条）且没有成功日志打断。
- **冷却机制**：进入熔断后，守护脚本等待配置的时间（默认 5 分钟）再重启主脚本；支持指数退避或手工指定。
- **状态记录**：每次熔断与重启原因通过 `logging` 输出，并写入守护脚本的本地日志文件。

### 5. 配置与可观察性
- **配置容器**：`dataclasses.dataclass` 定义 `SupervisorConfig`，集中管理命令、阈值、冷却时间、最大重启次数等。
- **加载方式**：结合 `argparse` 或环境变量，允许运维在命令行覆盖默认参数。
- **健康快照**：封装 `HealthSnapshot` 数据类，包含当前运行状态、失败统计、累计重启次数、已运行时长等，方便外部查询或写入文件。

## 流程概述
1. 守护脚本启动并加载配置。
2. 调用 `asyncio.create_subprocess_exec` 启动主脚本，同时开始异步读取 stdout/stderr。
3. 日志行经由 `FailurePatternDetector` 解析并更新滑动窗口/健康快照。
4. 若满足熔断条件，则向子进程发送 `SIGINT` → `SIGTERM` → `SIGKILL`，确保优雅停止。
5. 记录熔断事件，等待冷却时间后重新进入第 2 步。
6. 重复以上循环直到人工终止或达到最大重启次数。

## 关键优势
- **零侵入**：不修改原有任务管理、数据处理代码，便于维护。
- **可靠性**：及时识别 Yunwu API 集中故障，避免任务长时间卡死。
- **透明度**：实时输出健康指标，运维人员可以随时掌握进度与异常。
- **可扩展性**：阈值、冷却策略、展示方式等参数均可配置，适配不同运行环境和供应商行为。
