# A 股日内行情粒度与术语

本文档统一项目中 `Tick`、分笔成交、行情快照和分钟 K 线的命名，避免把网页展示口径误写成交易所逐笔数据。

## 项目采用的分层

| 层级 | 项目标准名称 | 一条记录代表什么 | 当前来源 |
| --- | --- | --- | --- |
| L0 | 严格逐笔事件（true tick） | 单笔成交，或单笔委托/撤单；通常需要事件序号和精细时间戳 | 当前没有 A 股数据源 |
| L1 | 分笔成交聚合（tick-like） | 数秒窗口内多笔成交的汇总，含展示价格、手数、笔数和方向 | 东方财富 `details/get`、`details/sse`；Tushare `realtime_tick(src=dc)` 概念相近 |
| L1-S | 行情快照 | 某一时刻最新价、累计量额及可用时的买卖档位状态 | 东方财富 `stock/get`、Tushare `realtime_quote` |
| L2 | 分钟 K 线 | 一分钟内成交聚合后的开、高、低、收、成交量和成交额 | Tushare `stk_mins`、`rt_min`；东方财富 `trends2/get` |
| L3 | 日线及以上 | 一个交易日或更长周期的聚合行情 | Tushare `daily` 等 |

## 东方财富成交数据的准确称呼

东方财富 `details/get` 和 `details/sse` 返回类似：

```text
13:12:36,15.78,444,42,2
```

字段依次为：

```text
时间,展示成交价,成交量（手）,底层成交笔数,方向代码
```

一行已经包含 `42` 笔成交，因此它不是“一行对应一笔成交”的严格 Tick。项目统一称为：

```text
约 3 秒粒度的分笔成交聚合（tick-like）
```

`details/sse` 只是把这种聚合结果通过长连接增量推送，并不会恢复已经被上游合并的单笔成交、委托和撤单。

## Tushare `stk_mins` 的准确称呼

`stk_mins` 是标准分钟 K 线，字段为：

```text
ts_code, trade_time, open, close, high, low, vol, amount
```

它不是 Tick，也不是撮合引擎本身。更准确的表述是：上游行情供应商基于成交数据，按一分钟窗口聚合生成 OHLCV：

```text
open   窗口内第一笔成交价
high   窗口内最高成交价
low    窗口内最低成交价
close  窗口内最后一笔成交价
vol    窗口内累计成交量（当前接口单位：股）
amount 窗口内累计成交额（当前接口单位：元）
```

“撮合”发生在交易所交易系统；分钟 K 线是对撮合产生的成交结果做后续时间聚合。因此项目中避免使用“分钟级撮合”这一说法。

## Tushare 是否有 A 股 Tick 数据

Tushare 文档中与 A 股 Tick/分笔接近的接口有：

| 接口 | 实际语义 | 历史能力 | 当前项目实测 |
| --- | --- | --- | --- |
| `realtime_quote` | 爬虫版实时盘口快照，含现价、累计量额和买卖五档 | 没有正式历史回查 | 新浪来源可用；属于快照，不是逐笔事件 |
| `realtime_tick` | 爬虫版当日分笔成交，支持 `src=sina` 或 `src=dc` | 只描述当日开盘以来数据，不是历史数据库 | 旧 `get_today_ticks` 路径已解析失败；不能作为当前可靠生产源 |
| `rt_min` | A 股实时分钟 K 线 | 实时分钟，不是 Tick | 当前自定义网关盘中返回空/不可用 |
| `stk_mins` | A 股历史分钟 K 线 | 可回查多年分钟数据 | 当前网关可用，但今天盘中查询为空，盘后入库 |

文档目录中另有“历史 Tick 行情”接口，但属于期货数据，不是 A 股历史逐笔。

因此当前结论是：

- Tushare 有一个概念上类似东方财富分笔聚合的 A 股爬虫接口 `realtime_tick`，并可选东方财富来源；
- 它不是 Tushare Pro 正式存储的 A 股历史逐笔数据库，质量、稳定性和历史回补没有保证；
- 当前项目没有获得严格意义上的 A 股历史逐笔成交、逐笔委托和撤单数据；
- 若研究要求 true tick，需要交易所授权 Level-2、券商 Level-2 或合规专业行情商，并同时确认序号、重传、历史保存和使用许可。

## 聚合与对账关系

完整覆盖一分钟的分笔成交聚合，理论上可以继续生成分钟 OHLCV：

```text
分笔聚合序列
  -> 第一价 / 最高价 / 最低价 / 最后一价
  -> 成交手数求和 × 100
  -> 一分钟 OHLCV
```

但网页分笔中的一行可能包含多笔成交，只给一个展示价格，因此用 `价格 × 聚合手数` 反推成交额可能有误差。SSE 监听窗口不完整、断线没有回补或分钟标签规则不同，也都会导致与 `stk_mins` 无法严格对齐。
