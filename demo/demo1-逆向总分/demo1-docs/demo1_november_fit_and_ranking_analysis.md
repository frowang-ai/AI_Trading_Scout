# 逆向总分模型：11 月拟合质量与排序能力分析

> 数据来源：`train_full_november.py` + `analyze_total_score_fit.py`  
> 训练集：11 月全量数据的 80%（约 5.87 万条）  
> 测试集：11 月剩余 20%（约 1.47 万条）  

---

## 1. 回归拟合质量（数值精度）

### 1.1 训练集（11 月 80%）

- `R² = 0.8840`
- `MAE = 2.26`
- `RMSE = 3.08`
- 误差分布：
  - 平均误差：`0.0004`
  - 标准差：`3.08`
  - 最小误差：`-20.31`
  - 最大误差：`12.73`

**解读：**

- 训练集 R² 接近 0.89，说明模型已经非常接近外部“总分”算法的非线性结构。
- MAE≈2.3、RMSE≈3.1，相对于总分标准差 9.0（见训练脚本输出），**数值误差约为 1/3 标准差**，属于拟合较好但不过拟合的区间。
- 误差均值几乎为 0，说明整体没有明显的系统性偏差（比如整体高估或低估）。

### 1.2 测试集（11 月 20%）

- `R² = 0.7320`
- `MAE = 3.32`
- `RMSE = 4.65`
- 误差分布：
  - 平均误差：`-0.0228`
  - 标准差：`4.65`
  - 最小误差：`-30.62`
  - 最大误差：`18.26`

**解读：**

- 测试集 R² 仍有 0.73，说明在完全未见过的样本上，模型仍能解释 70%+ 的方差，**泛化能力是稳定的**。
- 相比训练集，MAE 和 RMSE 有自然上升（3.32 vs 2.26，4.65 vs 3.08），属于合理的泛化落差，没有出现严重的过拟合迹象。
- 误差均值接近 0，说明在测试集上也不存在明显的整体偏高/偏低偏差。

**小结：**

- 数值维度上，模型在训练集上非常贴近目标，在测试集上略有退化但仍然稳健；
- 若仅以“预测总分本身”为目的，当前精度已经可以满足大部分分析需求。

## 2. 排序一致性（Spearman/Kendall）

“总分”的主要用途往往是**排序选股**，因此排序相关性比 R² 更关键。

### 2.1 训练集

- 全样本（所有 11 月数据混在一起）：
  - `Spearman ρ = 0.9442`
  - `Kendall τ = 0.8041`
- 按交易日分组（20 个交易日）：
  - 每日 Spearman 在 `[0.915, 0.955]` 区间
  - 每日 Kendall 在 `[0.756, 0.817]` 区间

**解读：**

- Spearman 0.94+、Kendall 0.80+ 属于**极强排序一致性**，说明在训练集上：
  - 总分的相对大小关系与真实算法几乎完全一致；
  - 任意两只股票之间，大约 80% 的配对排序是正确的。

### 2.2 测试集

- 全样本：
  - `Spearman ρ = 0.8803`
  - `Kendall τ = 0.7076`
- 按交易日分组：
  - 每日 Spearman 大致在 `[0.82, 0.90]` 之间
  - 每日 Kendall 大致在 `[0.64, 0.73]` 之间

**解读：**

- 测试集 Spearman 仍然接近 0.88，说明在未见过的样本上，**排序结构依然保持非常强的一致性**。
- Kendall≈0.71 意味着在测试集上，有 70% 左右的股票对排序方向是正确的，这对于选股和分层来说已经非常有参考价值。
- 和训练集对比：
  - Spearman 从 0.94 降到 0.88（约 6% 下降）
  - Kendall 从 0.80 降到 0.71（约 11% 下降）
  - 整体符合“有一定复杂度但不过拟合”的直觉。

**小结：**

- 从“排序一致性”的角度看，这个模型对真实总分的排序结构拟合得非常好；
- 只要业务侧更看重“谁比谁高”而不是“精确分值”，当前模型已经相当接近外部算法。

## 3. Top-N 选股能力（重叠率）

我们关心的问题：  
> 如果只看“前 N 名”，模型挑出来的股票与真实算法的前 N 名有多少重叠？

### 3.1 训练集（按日统计的重叠率平均值）

- Top-50：**57.6%**
- Top-100：**65.1%**
- Top-200：**73.7%**

**解读：**

- 以每天为单位：
  - 预测的 Top-50 里，平均有约 29 只股票是真的在真实 Top-50 中；
  - 预测的 Top-100 里，平均有约 65 只股票是真的在真实 Top-100 中；
  - 预测的 Top-200 里，平均有约 147 只股票是真的在真实 Top-200 中。
- 随着 N 增大，重叠率明显提升，说明模型对“高分股票”的捕捉是有层次结构的。

### 3.2 测试集（按日统计的重叠率平均值）

- Top-50：**66.8%**
- Top-100：**73.5%**
- Top-200：**78.3%**

**解读：**

- 有意思的一点是：在测试集上，Top-N 重叠率反而略高于训练集，这通常有两种可能：
  1. 训练集分布略复杂、噪声更大；  
  2. 随机划分导致测试集上整体“更规整”，模型更容易对高分股票给出正确排序。
- 以 Top-100 为例：
  - 每天的前 100 名中，约有 73 只股票是与真实算法一致的；
  - 错误的 27 只股票，大概率仍然集中在高分区域，而不是完全随机。

**小结：**

- 从“Top-N 选股”视角，模型在测试集上的表现已经非常可用：
  - 如果策略是“每天买入真实 Top-100”，用当前模型的 Top-100 作为近似替代，**大概 70%+ 的持仓会是一致的**；
  - 对于需要 Top-200 作为选股池的策略，重叠率接近 80%，误差主要体现在边缘样本上。

## 4. 综合评估与业务建议

综合回归拟合、排序一致性、Top-N 重叠率三个角度，可以得出以下结论：

1. **数值拟合质量**  
   - 训练集 R²≈0.88，测试集 R²≈0.73，整体数值拟合能力较强；
   - 误差分布没有明显偏高/偏低的系统性偏差。

2. **排序能力**  
   - 测试集 Spearman≈0.88、Kendall≈0.71，说明**排序结构高度一致**；
   - 这对分层选股、构建打分因子非常有利。

3. **Top-N 选股能力**  
   - 测试集 Top-100 重叠率≈73.5%、Top-200≈78.3%，说明在实际“高分股票池”构建上，当前模型非常接近真实算法。

4. **业务可用性判断**  
   - 如果业务场景是：
     - 构建 Top-100~200 的选股池；
     - 做分层（如五分位、十分位）排序；
     - 把“逆向总分”作为多因子模型中的一个因子；
   - 那么 **当前模型已经具备直接实盘使用的条件**。
   - 若业务场景是极度依赖“精准 Top-50”的策略，可以考虑进一步：
     - 针对高分区间单独优化（比如只对总分>某阈值建模）；
     - 结合排序型目标（LambdaRank / LTR）做混合训练。

## 5. 因子族级别解释（全局）

在两步跑流程中，`analyze_total_score_fit.py` 已经自动完成了：

- 载入或重新计算 11 月上的 SHAP 全局特征重要性：
  - 输出：`output_full/feature_importance.csv`
  - 内容：每个原子特征的平均 |SHAP|，反映对总分的全局贡献度。
- 按“特征名前缀”进行因子族聚合：
  - 输出：`output_full/feature_importance_grouped.csv`
  - 规则示例：
    - `pe_ttm`、`pe_lyr` → 分到同一组 `pe`
    - `pb_mrq`、`pb_ttm` → 分到组 `pb`
    - `volume_1d`、`volume_5d` → 分到组 `volume`
    - 没有下划线的特征统一分到组 `other`

通过这两个文件，可以直接回答类似问题：

- 哪一类因子（估值、动量、成交量、波动率、大小市值等）在逆向总分里权重最高；
- Tushare 的哪些原始字段被模型判定为“核心驱动因子”，哪些几乎没有被用到。

这部分目前是面向定量研究使用的数据输出，后续可以在需要时再整理成图表或文字说明。

## 6. 局部解释：单票/单天总分拆解

同样在 `analyze_total_score_fit.py` 中，已经实现了单票/单日的 SHAP 级别拆解：

- 自动从 11 月测试集的 `prediction_nov_test.csv` 中选取一只“误差最大的股票”作为代表样本；
- 在这只股票对应交易日上，计算每个特征的 SHAP 值，并生成局部解释图：
  - 输出：`output_full/local_shap_{ts_code}_{trade_date}.png`
  - 图中展示：
    - 横轴：SHAP 贡献值（正值拉高总分，负值拉低总分）
    - 纵轴：该样本最重要的若干个特征（按 |SHAP| 排序）

配合原始特征值，可以定性回答：

- “这一天，这只股票为什么被打了这么高/这么低的分？”
- “是因为涨跌幅、估值、换手还是某些技术指标主导了总分？”

如果后续需要，我们可以从这些 `local_shap_*.png` 中挑一两个典型案例，单独写一节“案例分析”，做成类似研究报告的风格。
